# Developer cockpit
The local Tutorial/index.html is a responsive developer cockpit. Keep project identity, next steps, run/test commands, diagnostic evidence, close-item checklist and the source workflow feedback loop visible. Use the same plain dark/navy/blue visual language as Groove Lab; do not copy the end-user practice interface into development instructions.


T.1.2 exposes the current song bank below the score, so transport and the teaching map remain adjacent. Color-coded section borders/backgrounds separate library, player, score, song bank and controls; instrument lanes have tinted cells and their own accent. Ornament letters, labels and outlines supplement color. Desktop controls scroll independently; two-bar maps scroll horizontally on narrow screens rather than expanding page width.

Practice flow: choose a genre → load one of five referenced songs → inspect its note/source/tempo conversion → play → add authored ornaments or open the full map. Repeated cell clicks reach ghost/drag/flam/rest; triplet tool selects its span. Reset and song loading clear manual edits deliberately; local save/JSON retain the entire exercise. Keep these interactions and their shared CLI/MCP equivalents in the cockpit.

T.1.3 adds three selectable genres (5/4, single-pedal metal, tom melody), 75 linked references and a reference stage at Complexity 4. The lab button stays compact and default-off; opening it shows three cards with descriptions. Snapshot state belongs to the engine, so a user can capture A, tune sound in another application tab, and return to compare B. Gap/ladder are visibly optional; hiding them disables playback effects. Spotify and YouTube remain separately labeled beside each song; narrow layouts wrap the links below the title and load button. Drag preparation dots reflect the actual preceding swung cells rather than placing a flam-like symbol at the middle of its field.
